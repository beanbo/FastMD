# FastMD — план развития

> Версия плана: 19.09.2026, после v0.2.0 (этап 1 выполнен). План заменяет прежний `ROADMAP.md`.
> Источники приоритетов: [REPORT.md](../REPORT.md), [research/06 §5, §10](../research/06-product-ux-landscape.md) (частоты функций в реальных README) и ваши пожелания.

## 0. Принципы (действуют для каждой задачи)

1. **Скорость — главная цель.** Функция не может ухудшить старт. На критическом пути первого кадра разрешено только чтение файла, разбор, вёрстка первого экрана и отрисовка на CPU.
   - Всё новое запускается после первого кадра, в фоне или по действию пользователя.
   - На критическом пути запрещены GPU-устройство, COM/WinRT, сеть, WebView2, декодирование картинок и загрузка «тяжёлых» DLL.
   - Бюджет: `t_content(FastMD) − t_content(baseline-win32)` ≤ 0 мс на medium и ≤ +15 мс на large, в одном чередующемся прогоне `bench.py`. Сейчас FastMD на ~15 мс *быстрее* эталона (контрольный замер v0.2.0 — `bench/results/guard-v0.2.0.json`).
2. **Каждая задача закрывается тремя проверками:**
   - замер скорости — команда в §2;
   - UI-тест — `python app/tests/ui_smoke.py`, для новой функции добавляется своя проверка;
   - визуальная проверка скриншотами, обычно на светлой и тёмной теме.
3. **Безопасность по умолчанию.** Документ — недоверенный ввод.
   - Ссылки открываются по белому списку схем.
   - Сеть только по явной настройке.
   - Парсеры проходят фаззинг.
   - Никакого выполнения скриптов из документа.
4. **Windows-only — осознанное решение.** Движок построен на DirectWrite, переносимость не цель.

## 2. Как мы работаем (процесс)

| Шаг | Команда / правило |
|---|---|
| Сборка для разработки | `pwsh -File app/build.ps1` → `app/build/Release/FastMD.exe` |
| Тест скорости | `python bench/harness/bench.py run fastmd-app,baseline-win32 --doc small,medium,large --runs 12` (перед замером не должно быть других запущенных копий этого exe) |
| UI-тест | `python app/tests/ui_smoke.py` |
| Публикация (ваша рабочая копия) | `pwsh -File app/publish.ps1` → `app/out/Release/FastMD.exe`; работает, даже если документы открыты |
| Коммиты | по одному на завершённую задачу, сообщение по-английски, в `CHANGELOG.md` одна строка по-русски |
| Версии | SemVer: 0.x.y до релиза 1.0; номер в `project(FastMD VERSION …)` в `app/CMakeLists.txt` |
| Релиз | тег `vX.Y.Z` и GitHub Release с zip (exe, README, лицензии), примечания из `CHANGELOG.md` |

Размер задачи: **S** — до полудня, **M** — 1–2 дня, **L** — 3–5 дней, **XL** — 1–2 недели работы опытного разработчика. Со мной обычно быстрее, но проверки занимают своё время.

**2.1 md4c master.** Сделано 20.09.2026, кроме набора по спецификации.
- Закреплён коммит master `7fc1815a` (17.09.2026). Своих патчей не потребовалось: UTF-16 поддержан в самой библиотеке (`MD4C_USE_UTF16`).
- `MD_DIALECT_GITHUB` в новой версии уже включает `MD_FLAG_FOOTNOTES` и `MD_FLAG_ADMONITIONS`, поэтому выноски `> [!NOTE]` теперь приходят блоком `MD_BLOCK_ADMONITION`, а не цитатой. Наш прежний разбор по тексту оставлен запасным.
- Сноски: ссылка `[^1]` рисуется как `[1]` и ведёт к определению, определения нумеруются и возвращают стрелкой. Якоря не-заголовков живут в `Doc::anchors`.
- Содержимое определения md4c присылает без блока абзаца, как в плотных списках, — сборщик начинает лист сам.
- *Осталось:* прогон CommonMark 0.31.2 (652 примера) и GFM именно в UTF-16-сборке; проверка автоссылок с точкой на конце.

**2.2 HTML-подмножество.** Разбор сырого HTML из md4c в маленький DOM, отрисовка тем же движком. Поддерживаются:
- `<img src width height align alt>`, в том числе внутри `<a>` (бейджи-ссылки);
- `<p align=center>` и `<div align=center>` — центрирование логотипов и бейджей;
- `<br>`, `<hr>`;
- `<details><summary>` — сворачиваемый блок, свёрнут по умолчанию и раскрывается кликом;
- `<picture><source media="(prefers-color-scheme: dark)">` — картинка под тему;
- `<sub>`, `<sup>`, `<kbd>` (клавиша в рамке), `<b>/<strong>`, `<i>/<em>`, `<code>`, `<a href>`, `<a name/id>` (якоря);
- простые `<table>/<tr>/<td>/<th>` без colspan (colspan позже).

Остальные теги выводятся как текст без тегов. Скрипты, стили и iframe никогда не исполняются.
*Готово, когда:* 20 популярных README выглядят как на GitHub по скриншот-сравнению (2.10).

**2.3 Удалённые картинки.**
- Загрузка через WinHTTP в фоне, строго после первого кадра. Место резервируется по `width/height` из HTML или по заголовку файла, чтобы вёрстка не прыгала.
- Дисковый кэш `%LOCALAPPDATA%\FastMD\cache` (LRU, 200 МБ) с учётом ETag/Last-Modified.
- Ограничения: таймауты, максимальный размер, только https (http — по настройке).
- Настройка приватности «всегда / спрашивать / никогда»: трекинг-пиксели раскрывают IP. По умолчанию «всегда», как на GitHub.
- Анимированные GIF показываются первым кадром; анимация — позже и опционально.

**2.4 SVG.** Библиотека lunasvg (C++, MIT) растеризует SVG в DIB с поддержкой текста (бейджи shields.io). Внешние ссылки внутри SVG запрещены. Растры кэшируются по размеру и DPI.

**2.5 Подсветка языков.** Сделано 21.09.2026 — но не через Lexilla.
- *Решение изменено:* Lexilla — это ~4 МБ исходников, свой интерфейс документа и таблица стилей на каждый лексер. Наш подсветчик уже устроен как реестр языков: строка таблицы = синтаксис комментариев и строк плюс список ключевых слов. Добавить язык стоит одну строку, поэтому 38 новых языков (всего 55 записей, 163 синонима имени) обошлись без новой зависимости и без роста exe на мегабайты.
- Метка языка в углу блока кода сделана; она же закрывает метку «диаграмма» для ```mermaid (задача 2.9).
- Если понадобится настоящая грамматика (например, для подсветки в экспорте), Lexilla можно добавить отдельной DLL по образцу `fastmd-svg.dll`.

**2.6 Emoji-шорткоды.** Таблица gemoji (~1,9 тыс. имён) вшивается сжатой: `:rocket:` → 🚀. Работает вне кода.

**2.7 Front matter.** Компактная таблица «ключ: значение». Сложный YAML (списки, вложенность) показывается как сейчас, блоком YAML. Блок сворачивается.

**2.8 Якоря заголовков.** При наведении слева от заголовка появляется значок 🔗. Клик копирует ссылку `файл.md#slug` и прокручивает к заголовку.

**2.10 Визуальная регрессия.** Сделано 21.09.2026: `app/tests/readme_check.py` + список `app/tests/readmes.txt` (15 репозиториев: vscode, react, rust, cpython, node, tailwind, svelte, deno, ollama, md4c, lunasvg, bat, fzf, neovim, obsidian).

**3.1 Копирование с форматированием.** Кроме текста в буфер кладутся `CF_HTML` и RTF: вставка в Word или Outlook сохраняет заголовки, жирный текст, ссылки, таблицы и код. Сделано 21.09.2026 в `src/copy.cpp`: один проход по блокам выделения строит обе записи сразу.

**3.2 Копирование как Markdown.** Сделано 21.09.2026.
- Карта «позиция в тексте → позиция в исходнике» (`Doc::srcMap`). Строится из указателей md4c: `ptr − src` работает для всего текста, проверено на 145 тыс. вызовов.
- Пункт меню «Копировать как Markdown» и Ctrl+Shift+C. Выделение расширяется до границ строк, переводы строк — CRLF.

**3.3 Клавиатурное выделение.** Сделано 21.09.2026. Shift+стрелки, Shift+Home/End, Ctrl+Shift+стрелки (по словам), Ctrl+Shift+Home/End и Shift+PageUp/PageDown — с видимым курсором, который появляется только при выделении с клавиатуры и держит колонку при движении вверх-вниз. Курсор рисуется вместе с документом, поэтому прокрутка уносит его с текстом и частичная перерисовка кадра продолжает работать.

**3.4 Печать и экспорт в PDF.** Сделано 21.09.2026 (`src/print.cpp`, `src/canvas_print.cpp`).
- Вёрстка тем же движком под DPI принтера: окно на время печати одалживает свою геометрию бумаге и получает её обратно вместе с местом чтения.
- Страницы режутся по границам блоков; блок выше страницы — по строкам текста или строкам таблицы (`BlockSplitY`).
- Колонтитулы: имя файла сверху, «N из M» снизу. Палитра всегда светлая.
- Текст уходит глифами GDI (`ExtTextOut` + `ETO_GLYPH_INDEX`) со шрифтом, сделанным из того же начертания DirectWrite, поэтому в PDF он остаётся текстом; цветные эмодзи рисуются слоями COLR. Проверка: UI-тест печатает документ в PDF и читает его обратно через pypdf.
- Выбор принтера, бумаги и диапазона страниц — системный диалог. PDF — через «Microsoft Print to PDF» с именем файла, заданным заранее (второго диалога нет).
- *Осталось:* своего окна предпросмотра нет (в системном диалоге Windows его тоже нет) — предпросмотром служит экспорт в PDF; текст справа налево печатается слева направо.

**3.5 Перетаскивание наружу.** Сделано 21.09.2026 (`src/drag.cpp`). Выделенный текст (текст + CF_HTML + RTF), ссылка (текст + `UniformResourceLocatorW`) и картинка (`CF_DIB` + `CF_HDROP` для файла на диске) перетаскиваются в другие приложения через `DoDragDrop`; COM поднимается при первом перетаскивании. Порог сдвига — системный (`SM_CXDRAG`), нажатие внутри выделения снимает его только если мышь не двинулась. Автотест проверяет набор форматов (`Q_DRAG`); сам цикл перетаскивания — за системой и проверяется руками.

**5.5 Подпись.** Azure Trusted Signing (~$10/мес) или OV-сертификат. Без подписи SmartScreen предупреждает при первом запуске; подпись также может ускорить проверку Defender при запуске.
