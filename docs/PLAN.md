# FastMD — план развития

> Версия плана: 19.09.2026, после v0.1.1. План заменяет прежний `ROADMAP.md`.
> Источники приоритетов: [REPORT.md](../REPORT.md), [research/06 §5, §10](../research/06-product-ux-landscape.md) (частоты функций в реальных README) и ваши пожелания.

---

## 0. Принципы (действуют для каждой задачи)

1. **Скорость — главная цель.** Функция не может ухудшить старт. На критическом пути первого кадра разрешено только чтение файла, разбор, вёрстка первого экрана и отрисовка на CPU.
   - Всё новое запускается после первого кадра, в фоне или по действию пользователя.
   - На критическом пути запрещены GPU-устройство, COM/WinRT, сеть, WebView2, декодирование картинок и загрузка «тяжёлых» DLL.
   - Бюджет: `t_content(FastMD) − t_content(baseline-win32)` ≤ 0 мс на medium и ≤ +15 мс на large, в одном чередующемся прогоне `bench.py`. Сейчас FastMD на ~20 мс *быстрее* эталона.
2. **Каждая задача закрывается тремя проверками:**
   - замер скорости — команда в §2;
   - UI-тест — `python app/tests/ui_smoke.py`, для новой функции добавляется своя проверка;
   - визуальная проверка скриншотами, обычно на светлой и тёмной теме.
3. **Безопасность по умолчанию.** Документ — недоверенный ввод.
   - Ссылки открываются по белому списку схем.
   - Сеть только по явной настройке.
   - Парсеры проходят фаззинг.
   - Никакого выполнения скриптов из документа.
4. **Windows-only — осознанное решение.** Движок построен на DirectWrite, переносимость не цель.

## 2. Как мы работаем (процесс)

| Шаг | Команда / правило |
|---|---|
| Сборка для разработки | `pwsh -File app/build.ps1` → `app/build/Release/FastMD.exe` |
| Тест скорости | `python bench/harness/bench.py run fastmd-app,baseline-win32 --doc small,medium,large --runs 12` (перед замером не должно быть других запущенных копий этого exe) |
| UI-тест | `python app/tests/ui_smoke.py` |
| Публикация (ваша рабочая копия) | `pwsh -File app/publish.ps1` → `app/out/Release/FastMD.exe`; работает, даже если документы открыты |
| Коммиты | по одному на завершённую задачу, сообщение по-английски, в `CHANGELOG.md` одна строка по-русски |
| Версии | SemVer: 0.x.y до релиза 1.0; номер в `app/res/fastmd.rc` |

Размер задачи: **S** — до полудня, **M** — 1–2 дня, **L** — 3–5 дней, **XL** — 1–2 недели работы опытного разработчика. Со мной обычно быстрее, но проверки занимают своё время.

Цель — чтобы ридером было приятно пользоваться каждый день.

**1.2 Горизонтальная прокрутка.**
- Блок кода или таблица шире колонки получает своё смещение по X.
- Прокрутка: Shift+колесо над блоком и тачпад (`WM_MOUSEHWHEEL`), тонкий ползунок внизу блока при наведении.
- Выделение и поиск учитывают смещение: при переходе к совпадению блок сам докручивается.
- Опция «переносить строки в коде» — пункт меню, по умолчанию выключена.
- *Готово, когда:* строка длиной 200 символов читается целиком, UI-тест прокручивает блок и находит текст в конце строки.

**1.3 Оглавление.**
- Панель слева, по Ctrl+Shift+O или кнопкой. Строится из `Doc::headings` после первого кадра.
- Подсвечивает текущий раздел при прокрутке, клик переходит к заголовку.
- Узкое окно: панель показывается поверх текста; широкое: сдвигает колонку.
- Состояние «открыта/закрыта» запоминается.
- *Готово, когда:* на medium.md 24 раздела, клик по пятому заголовку прокручивает к нему, текущий раздел подсвечивается.

**1.4 Позиция чтения.**
- Для последних 200 файлов хранится `{путь, размер, время изменения, scrollY-якорь}` (блок + смещение). Место: `%LOCALAPPDATA%\FastMD\positions.bin`, читается *после* первого кадра.
- При повторном открытии документ плавно доезжает до места.
- Если файл изменился, позиция ищется по тексту заголовка ближайшего раздела.

**1.5 Строка поиска 2.0.**
- Кнопки ↑ ↓ ✕ и мышь; переключатели «Учитывать регистр» (Alt+C) и «Слово целиком» (Alt+W).
- Сохранение запроса между документами.
- Совпадения видны на полосе прокрутки как метки.
- Ввод с IME (китайский, японский): окно ввода живёт в отдельном потоке — UI-поток документа остаётся без TSF ради скорости старта.

**1.6 Недавние документы.** Без файла в аргументах вместо пустого экрана показывается список последних 10 документов, с поиском по названию. Плюс Jump List в панели задач (`SHAddToRecentDocs` уже вызывается, остаётся категория «Недавние»).

**1.7 Клавиатура.**
- Tab / Shift+Tab по ссылкам с видимым фокусом, Enter открывает.
- Правый клик по ссылке: «Открыть», «Копировать адрес ссылки»; по картинке: «Копировать картинку», «Открыть файл картинки».

**1.8 Ширина колонки.** Узкая (560), обычная (680), широкая (900) или во всю ширину. Через меню и Ctrl+Alt+← / →.

**1.9 Окно настроек.**
- Опции: тема, шрифт текста (Segoe UI Variable или «книжный» Sitka с оптическими размерами), размер шрифта, ширина колонки, редактор для Ctrl+E, картинки из сети («всегда / спрашивать / никогда» — см. 2.3), анимация прокрутки, язык интерфейса.
- Реализация: окно на Win32, собственная отрисовка тем же движком, открывается только по команде.

**1.10 Редактор.** Настройка «Открывать в…» с автопоиском VS Code, Void, Cursor, Notepad++, Блокнота и возможностью указать свой exe. По умолчанию действие «Изменить» из системы.

### Этап 2 — v0.3 «README с GitHub выглядит как на GitHub»

Цель — паритет рендера с GitHub на реальных README. По данным исследования 06: HTML в 76 % README, удалённые картинки в 85 %, SVG-бейджи в 73 %.

| № | Задача | Размер |
|---|---|---|
| 2.1 | Обновление md4c: сноски, alerts, регрессионный набор | M |
| 2.2 | HTML-подмножество (мини-DOM) | L |
| 2.3 | Удалённые картинки | L |
| 2.4 | SVG (включая бейджи) | M |
| 2.5 | Подсветка через Lexilla | M |
| 2.6 | Emoji-шорткоды `:smile:` | S |
| 2.7 | Front matter как таблица свойств | S |
| 2.8 | Якорь при наведении на заголовок | S |
| 2.9 | Формулы и Mermaid «как код» (временно) | S |
| 2.10 | Визуальная регрессия на реальных README | M |

**2.1 md4c master.**
- Форк с закреплённым коммитом (0.6.0-dev) и нашим UTF-16-патчем.
- Флаги `MD_FLAG_FOOTNOTES` и `MD_FLAG_ADMONITIONS`; наш разбор alerts остаётся запасным.
- Проверить регрессию автоссылок с точкой на конце.
- В набор тестов входят CommonMark 0.31.2 spec (652 примера), GFM extensions и наши случаи — именно в UTF-16-сборке.
- *Готово, когда:* сноски кликабельны туда и обратно, тесты зелёные.

**2.2 HTML-подмножество.** Разбор сырого HTML из md4c в маленький DOM, отрисовка тем же движком. Поддерживаются:
- `<img src width height align alt>`, в том числе внутри `<a>` (бейджи-ссылки);
- `<p align=center>` и `<div align=center>` — центрирование логотипов и бейджей;
- `<br>`, `<hr>`;
- `<details><summary>` — сворачиваемый блок, свёрнут по умолчанию и раскрывается кликом;
- `<picture><source media="(prefers-color-scheme: dark)">` — картинка под тему;
- `<sub>`, `<sup>`, `<kbd>` (клавиша в рамке), `<b>/<strong>`, `<i>/<em>`, `<code>`, `<a href>`, `<a name/id>` (якоря);
- простые `<table>/<tr>/<td>/<th>` без colspan (colspan позже).

Остальные теги выводятся как текст без тегов. Скрипты, стили и iframe никогда не исполняются.
*Готово, когда:* 20 популярных README выглядят как на GitHub по скриншот-сравнению (2.10).

**2.3 Удалённые картинки.**
- Загрузка через WinHTTP в фоне, строго после первого кадра. Место резервируется по `width/height` из HTML или по заголовку файла, чтобы вёрстка не прыгала.
- Дисковый кэш `%LOCALAPPDATA%\FastMD\cache` (LRU, 200 МБ) с учётом ETag/Last-Modified.
- Ограничения: таймауты, максимальный размер, только https (http — по настройке).
- Настройка приватности «всегда / спрашивать / никогда»: трекинг-пиксели раскрывают IP. По умолчанию «всегда», как на GitHub.
- Анимированные GIF показываются первым кадром; анимация — позже и опционально.

**2.4 SVG.** Библиотека lunasvg (C++, MIT) растеризует SVG в DIB с поддержкой текста (бейджи shields.io). Внешние ссылки внутри SVG запрещены. Растры кэшируются по размеру и DPI.

**2.5 Lexilla.**
- Лексеры Scintilla / Notepad++ (100+ языков): инициализация 0,1–0,3 мс, скорость 22–36 МБ/с.
- Подсветка синхронная для видимых блоков, ленивая для остальных.
- Метка языка в углу блока кода.
- Нынешний эвристический подсветчик остаётся запасным для неизвестных языков.

**2.6 Emoji-шорткоды.** Таблица gemoji (~1,9 тыс. имён) вшивается сжатой: `:rocket:` → 🚀. Работает вне кода.

**2.7 Front matter.** Компактная таблица «ключ: значение». Сложный YAML (списки, вложенность) показывается как сейчас, блоком YAML. Блок сворачивается.

**2.8 Якоря заголовков.** При наведении слева от заголовка появляется значок 🔗. Клик копирует ссылку `файл.md#slug` и прокручивает к заголовку.

**2.9 Формулы и Mermaid как код.**
- Включается флаг md4c `MD_FLAG_LATEXMATHSPANS`: `$…$` и `$$…$$` показываются моноширинным шрифтом, как формула-код.
- Блоки ```mermaid получают метку «диаграмма».
- Настоящий рендер — на этапе 4.

**2.10 Визуальная регрессия.** Корпус из 30 реальных README: популярные репозитории, разные стили и языки. Для каждого эталонный скриншот GitHub-рендера (один раз, через браузер) и наш скриншот, отчёт с попиксельным diff и ручным просмотром. Корпус запускается перед каждым релизом.

### Этап 3 — v0.4 «Работа с текстом»

| № | Задача | Размер |
|---|---|---|
| 3.1 | Копирование с форматированием (HTML + RTF) | M |
| 3.2 | Копирование как Markdown (исходник) | M |
| 3.3 | Клавиатурное выделение | S |
| 3.4 | Печать и экспорт в PDF | L |
| 3.5 | Перетаскивание наружу (текст, ссылки, картинки) | S |

**3.1 Копирование с форматированием.** Кроме текста в буфер кладутся `CF_HTML` и RTF: вставка в Word или Outlook сохраняет заголовки, жирный текст, ссылки, таблицы и код.

**3.2 Копирование как Markdown.**
- Карта «позиция в тексте → позиция в исходнике». Строится из указателей md4c: `ptr − src` работает для всего текста, проверено на 145 тыс. вызовов.
- Пункт меню «Копировать как Markdown» и Ctrl+Shift+C.

**3.3 Клавиатурное выделение.** Shift+стрелки, Shift+Home/End, Ctrl+Shift+стрелки (по словам) — с видимым курсором, появляется только при выделении с клавиатуры.

**3.4 Печать и экспорт в PDF.**
- Вёрстка тем же движком под DPI принтера (GDI-печать), разбиение на страницы по границам блоков, колонтитулы (имя файла, номер страницы).
- Предпросмотр и выбор принтера — системный диалог. PDF — через «Microsoft Print to PDF».

**3.5 Перетаскивание наружу.** Выделенный текст, ссылки и картинки перетаскиваются в другие приложения (`DoDragDrop`; COM только в момент перетаскивания).

### Этап 4 — v0.5 «Формулы и диаграммы»

| № | Задача | Размер |
|---|---|---|
| 4.1 | Формулы: RaTeX | L |
| 4.2 | Mermaid: mmdr + запасной WebView2 | L |
| 4.3 | Проверки совместимости | M |

**4.1 RaTeX.**
- Rust-библиотека, совместимая с KaTeX, с C ABI: первая формула рендерится ≈0,6–1 мс, дальше ≈0,07 мс на формулу.
- Сборка через cargo в статическую lib, вызов через FFI.
- Отрисовка глифами DirectWrite в нашу канву, в фоновом потоке после первого кадра. Место под формулы оценивается заранее, в первом кадре — формула-код.
- Нужен Rust-тулчейн в сборке (есть).

**4.2 Mermaid.**
- mmdr (Rust) выдаёт SVG за ≈40–90 мс на диаграмму, в фоне; SVG растеризуется через lunasvg (2.4).
- Запасной путь для типов, которые mmdr не умеет: скрытый (cloaked) WebView2 рендерит SVG. Этот путь поднимается только в документах с mermaid, в одном экземпляре на процесс, SVG кэшируется на диске. Параметры: `htmlLabels:false`, virtual host только `.example`.

**4.3 Совместимость.** Набор из 100 формул (KaTeX-тесты) и 30 диаграмм разных типов, скриншот-сравнение с эталоном.

### Этап 5 — v0.6 «Интеграция с Windows и поставка»

| № | Задача | Размер |
|---|---|---|
| 5.1 | Выделение движка в статическую библиотеку | M |
| 5.2 | Панель просмотра Проводника (preview handler) | L |
| 5.3 | Эскизы .md в Проводнике (опционально) | M |
| 5.4 | Установщик без прав администратора | M |
| 5.5 | Подпись кода | S (+ оформление сертификата) |
| 5.6 | Автообновление | M |
| 5.7 | winget | S |

**5.1 Движок в библиотеку.** Модель, парсер, вёрстка, канва и вид уходят в `fastmd-core.lib`. Exe и будущая DLL превью используют её; нужна для 5.2 и 5.3.

**5.2 Preview handler.**
- In-proc DLL (`IPreviewHandler`, хостится в `prevhost.exe`) на том же движке.
- Цель — быстрее 100 мс против 0,6–1,4 с у PowerToys.
- Только чтение, без сети по умолчанию. Регистрация в HKCU.

**5.3 Эскизы.** `IThumbnailProvider`: миниатюра первого экрана документа.

**5.4 Установщик.**
- Per-user в `%LOCALAPPDATA%\Programs\FastMD`, без админа.
- Регистрирует ассоциацию, пункт «Открыть с помощью», ярлык в меню «Пуск» и запись в «Приложения» для удаления.
- Инструмент — Inno Setup или свой крошечный установщик на C++ (решим в задаче). MSIX не используем: виртуализация AppData замедляет файловый I/O.

**5.5 Подпись.** Azure Trusted Signing (~$10/мес) или OV-сертификат. Без подписи SmartScreen предупреждает при первом запуске; подпись также может ускорить проверку Defender при запуске.

**5.6 Автообновление.**
- Проверка GitHub Releases раз в сутки, после первого кадра, в фоне.
- Загрузка и проверка подписи.
- Замена exe через переименование, как в `publish.ps1`, чтобы не мешать открытым окнам.
- Уведомление «Доступна версия X», без навязчивости.

**5.7 winget.** Манифест в `microsoft/winget-pkgs`: установка одной командой `winget install FastMD`.

**6.2 Высокий контраст.** В режиме высокой контрастности Windows используются системные цвета (`GetSysColor`), подсветка кода отключается.

**6.3 Локализация.** Строки интерфейса выносятся в ресурсы, язык выбирается по системе с переключателем в настройках.

**6.4 Сбои.**
- Обработчик исключений пишет minidump в `%LOCALAPPDATA%\FastMD\crashes`.
- При следующем запуске — предложение открыть папку, отправка только вручную.
- Защита от «зависания» на патологических файлах: таймаут разбора в фоне, частичный показ.

**6.5 Фаззинг и безопасность.**
- libFuzzer (`/fsanitize=fuzzer` в MSVC 2022) для md4c + построителя модели, HTML-мини-DOM, SVG, заголовков картинок, YAML.
- ASan-сборка в CI.
- Ревью обработки ссылок и путей: UNC, `file:`, пути с `..`.

**6.6 Слабое железо.**
- Прогон харнесса на ноутбуке только с iGPU, 4 ядрами и экраном 4K / 150 %.
- Тест прокрутки (`--scroll-test`), память на больших файлах.
- По итогам: второй бэкенд отрисовки (D2D WARP/HW) и резидентный режим (7.1) — только если цифры этого потребуют.

**6.7 Документация.** README с GIF, страница проекта, таблица горячих клавиш, раздел о приватности.

**6.8 Релиз 1.0.**
- GitHub Release с установщиком и zip, запись в `CHANGELOG.md`, манифест winget.
- Финальный прогон: все проверки из §5.

## 7. Риски

| Риск | Что делаем |
|---|---|
| HTML-подмножество разрастается | Жёсткий список тегов (2.2). Остальное — текст. Критерий — корпус из 30 README |
| Сеть (удалённые картинки) замедлит старт | Только после первого кадра, строгие таймауты, дисковый кэш, место резервируется заранее |
| Rust-зависимости (RaTeX, mmdr) усложняют сборку | Готовые статические lib в репозитории или сборка cargo в CI. Запасной путь для диаграмм — WebView2 |
| UIA-провайдер трудоёмок | Отдельный этап (6.1), начинаем с минимального `TextPattern` |
| Ложные срабатывания антивирусов на неподписанный exe | Подпись (5.5), сборки только из CI |
| Регрессии скорости накапливаются по чуть-чуть | Бюджет §0, ночной замер с графиком, правило «каждый коммит не медленнее» |
